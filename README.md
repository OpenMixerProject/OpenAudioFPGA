# OpenAudioFPGA

Modular FPGA code base for the consoles of the [OpenMixerProject](https://github.com/OpenMixerProject).


## Layers

```
platforms/<console>_<fpga>/    top level: pin names, PLLs / DCMs, IO and DDR registers,
                               constraints, vendor project files
consoles/<console>/            console logic that every FPGA variant shares
rtl/core/                      generic audio core (openaudio_core)
rtl/periph/                    vendor-neutral building blocks for the console layers
rtl/aes50/                     AES50 core
ext/AES67/                     AES67 core (only for builds with AES67)
litex_soc/                     control SoC generator (LiteX) and the SPIBone fork
driver/spibone/                Linux driver of the control bus (host side)
```

## The generic core

`rtl/core/openaudio_core.vhd` contains the audio clock divider, the TDM8 receivers and
senders, the routing matrix, the control bus (SPI -> Wishbone) and the network cores (any number
of AES50 cores, AES67 core).

| Generic | Meaning |
|---|---|
| `G_TDM_LINES_IN` | number of TDM8 input lines (8 channels each) = sources of the matrix |
| `G_TDM_LINES_OUT` | number of TDM8 output lines = destinations of the matrix |
| `G_AES50_PORTS` | number of AES50 cores (0 = none) |
| `G_AES50_FIRST_LINE` | AES50 core *k* occupies the 6 lines `FIRST + 6k .. FIRST + 6k + 5` in both directions |
| `G_AES50_SUPPORT_44K1`, `G_AES50_UART_AUX`, `G_AES50_TDM_AUX`, `G_AES50_UART_FIFO_AW`, `G_AES50_UART_BAUD` | passed to the AES50 cores |
| `G_AES67` | with AES67 core (false: the AES67 sources are not needed) |
| `G_AES67_FIRST_LINE` | the AES67 core occupies the 4 lines `FIRST .. FIRST + 3` in both directions |
| `G_FS_SYNC_CNT`, `G_FS_ADVANCE` | alignment of the clock divider to the frame sync of the AES67 core, without AES67 to `fs_sync_i` |
| `G_PLATFORM_ID` | platform number in the CSR `core_info` |


### Control bus

The host reaches everything over one bus: LiteX SPIBone (4-wire SPI, mode 0) -> Wishbone,
generated by `litex_soc/generate.py` (module `openaudio_soc`, clocked with `clk50_i`) with the
burst-capable SPIBone fork in `litex_soc/spi_bone.py`. LiteX and migen are pinned in
`litex_soc/requirements.txt`; `litex_soc/setup_venv.sh` creates `litex_soc/.venv`, which
`build.sh` uses. Byte addresses, 32 bit words:

| Address | Size | Content |
|---|---|---|
| `0x00000000` | 64 KiB | CSRs: `ctrl` (reset, scratch, bus errors), `core` (`info`, `version`, `config` = `cfg_bits_o`), see `litex_soc/build/<family>/csr.csv` |
| `0x80000000` | 64 KiB | routing matrix: word *n* = destination channel `line * 8 + channel`, value = source `line * 8 + channel + 1`, 0 = off |
| `0x90000000` | 128 KiB | AES67 core (register window of its `aes67_bridge` `csr.csv`) |


On Linux the bus belongs to the `spibone` kernel driver in `driver/spibone` (`/dev/spibone0`),
which also configures the FPGA over the same SPI link and creates client devices from its
DT child nodes, e.g. the AES67 netdev (`aes67_eth` of the AES67 project).
## X32

`consoles/x32/x32_common.vhd`: startup sequence, CS2000 setup, AUX converter setup, UART
collector of the IO boards, UltraNet and the core.

| Line | Sources | Destinations |
|---|---|---|
| 0 - 1 | AD0 (XLR 1-16) | DA (XLR out 1-16) |
| 2 - 3 | AD1 (XLR 17-32) | UltraNet P16 A / B |
| 4 - 7 | expansion card | expansion card |
| 8 | AUX AD | AUX DA |
| 9 - 13 | DSP | DSP |
| 14 ... | AES50 cores, 6 lines each | |
| then | AES67 core, 4 lines | |

| `G_AES50_PORTS` | `G_AES67` | Port A | Port B | Lines |
|---|---|---|---|---|
| 1 | true | AES50 | AES67 | 24 |
| 2 | false | AES50 | AES50 | 26 |
| 1 | false | AES50 | unused | 20 |
| 0 | true | AES67 | unused | 18 |

With the AES67 core the CS2000 follows its PTP disciplined clock (x2), else the 16 MHz
oscillator (x3.072).

| | `x32_lattice` | `x32_spartan` |
|---|---|---|
| Default | 1 x AES50 + 1 x AES67 | 1 x AES50 |
| AES67 | yes | wired up (`create_project.tcl aes67`), but XST stops in the AES67 sources (`'succ` in the MAC `framing.vhd`) |
| AUX converters | M8000 ADC + PCM1690 DAC | CS42438 |
| Vendor parts | 2 PLLs, IO registers, DDR clock outputs (Clarity Designer, `ip/`) | DCM, BUFG, IDDR2 / ODDR2 (`ip/`) |

### Building

```
./build.sh lattice | xilinx | all
```

builds the bit files and prints resource utilisation and timing of each platform. Bit files,
reports and logs end up in `build/`.

| Variable | |
|---|---|
| `DIAMOND_DIR` | Lattice Diamond installation, e.g. `~/lscc/diamond/3.14` |
| `ISE_VM_HOST` | host name or IP address of the Xilinx ISE 14.7 VM |
| `ISE_VM_REPO` | path of this repository inside the VM |
| `ISE_VM_USER`, `ISE_VM_PASSWORD`, `ISE_VM_SETTINGS` | optional: user (default `ise`), password (default `xilinx`), ISE settings script |

By hand:

* Lattice: open `platforms/x32_lattice/x32_lattice.ldf` in Diamond, or `diamondc build.tcl [synth|map|par|bit]`
  in `platforms/x32_lattice`.
* Xilinx: `xtclsh create_project.tcl` in `platforms/x32_spartan` creates `build/x32_spartan.xise`,
  `xtclsh create_project.tcl build` also builds the bit file.

## WING Trion T55F484 (offline candidate)

The WING console uses the fork's shared core, routing RAM, LiteX SPIBone SoC and
AES50v2 `rtl/aes50` Gitlink (`bffe14e91636efe0c873adfc8244731d610f9e1c`).
The WING generator applies [its CDC patch](platforms/wing_trion/aes50-wing-cdc.patch)
to staged AES50v2 sources only. The upstream Gitlink and GPL-3.0-or-later
headers remain intact; X32 continues to use the unpatched submodule.
After `git submodule update --init` and setting up the pinned LiteX Python environment:

```sh
litex_soc/.venv/bin/python platforms/wing_trion/generate.py build/wing-b --aes50-ports 1
```

Compile the generated `wing-fpga.xml` with Efinity 2026.1.132 (`efx_run --flow
compile`, seed 1). `--aes50-ports 0`, `2` and `3` are non-deliverable measurement
profiles of the same design. Extra cores have synthetic RMII/sync stimulus and a
CSR-observable output reduction, not A/C pads. The B profile alone selects a
production-shaped CSR capability mask. That mask does not qualify the board.
See the [B-only CDC and timing audit](platforms/wing_trion/tests/cdc.md) for
offline verification and the remaining WING V1 measurement gates.

Manual clock targets: Si5351 CLK0/R2 **49.152 MHz**, CLK5/M3 **50.000 MHz**;
FPGA-generated DSP CLKIN 12.288 MHz, SPORT BCLK 24.576 MHz and FS 48 kHz.
The byte-exact `consoles/wing/profile-tdm16.json` defines stock pin directions,
separate in-phase TX/RX BCLK/FS, and slots 64/50/32/16. `profile.json` is the
**retired offline-only** TDM32 profile: 49.152 MHz SPORT violates the SHARC
slave-TX limit. The old Recovery images are not hardware audio profiles either.
No DSP FS/VALID until the actual clock source, DSP PLL/CCLK, speed grade, framing,
and both I/O directions have been qualified. T6/R7 are read-only observations;
the B sync net roles and live link are not proved. W9 resets A and B together.

`csr.csv`, `csr.json`, and `software/include/generated/csr.h` come from the
same LiteX generation as the image. `--bind build/wing-b` (output directory
first or last) verifies the native passive-x1 preamble and digests and produces
`manifest.candidate.json`; it does not create a trusted loader receipt. Boot
the image only under a separately qualified loader policy. ABI 2 has routing
base `0x80000000` (not the Recovery `0x1000`), 768 10-bit words, and OFF=0;
only IDs in `channels.sources` / `channels.destinations` are available.
See [SPIBone driver](driver/spibone/README.md) for SS0 vs SS1 and online checks.

For offline identity-only checks, see the [separate fabric-ID target](platforms/wing_trion/fabric_id/README.md).
It does not instantiate the mixer, SPORT, or AES50 and is not a substitute for the Port B image.
